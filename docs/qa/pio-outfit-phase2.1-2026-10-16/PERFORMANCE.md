# Phase 2.1 CPU·메모리 조사

**판정: PARTIAL. 이번 단계에서 렌더링 최적화는 적용하지 않았으며 성능 개선율을 주장하지 않는다.**

## 동일 조건 비교

macOS 27.0.1 (26A434), 같은 검증용 Mac Debug 앱, Routimori opt-in, 격리된 검토 데이터, 1040×900 창, 같은 진단 루트, 220pt 캐릭터 한 개, light 배경, 동일한 원본 4개를 미리 캐시에 준비한 조건이다. 타이밍 중 화면 캡처/영상 녹화는 하지 않았다. 각 샘플은 3초 안정화 후 1초 간격으로 프로세스 누적 CPU 시간과 RSS를 읽었다. 100%는 코어 하나이며 앱 프로세스 전체의 수치다. GPU/WindowServer/렌더 서버 비용은 포함하지 않는다.

0.000%는 이 짧은 누적 시간 표본의 해상도에서 증가가 검출되지 않았다는 의미다. CPU/GPU 비용이 문자 그대로 전혀 없다는 뜻이 아니다. 샘플은 서로 다른 실행 PID를 포함한다. RSS는 시스템 압력·페이지 회수 영향을 받아 감소하기도 했으므로, 표의 차이를 의상 한 장의 메모리 비용이나 개선량으로 해석하지 않는다. 동일하게 준비한 네 이미지가 모든 비교에 포함된다.

## 실제 애니메이션과 캐시 증거

- 점프 비교 전후 수동 계측에서 활성 rig 1개 / 실제 Core Animation track 3개를 확인했다. 이름만 점프로 바뀐 정지 상태를 비교한 것이 아니다. 새 iPhone 녹화의 위치 변화도 별도로 확인했다.
- 안정된 점프에서 host update, native refresh, layout transaction과 sourceLoads 수치가 증가하지 않았다. 현 표본에서는 프레임마다 SwiftUI 레이아웃이나 소스 재조회가 반복되는 병목 증거가 없었다.
- 30회 전환은 같은 PID에서 수행했다. 평균 약 0.363%, 최대 약 1.987%, RSS 95.81–95.91MiB. 캐시 4개 유지, 추가 sourceLoads 0회, 구성 갱신 30회였다. 같은 PID에서 뷰 제거 후 rig/track 모두 0, CPU 측정치 0%, RSS 82.95–83.06MiB였다.
- sourceLoads는 로컬 캐시에 들어간 성공적인 CGImage 조회 수다. 물리적인 PNG 디코더 호출을 계측한 수치가 아니므로 '디코딩 0회'로 과장하지 않는다.
- offscreen 파일명 조건은 실제로 뷰를 제거한 조건이다. 스크롤 밖에 살아 있는 뷰의 콜백/모든 구형 OS 경로를 런타임 검증한 것은 아니다.
- 약 30회의 짧은 전환에서 지속 증가나 활성 rig 누적은 관찰되지 않았다. 장시간 누수 부재, 전체 메모리 그래프, GPU/배터리/열 안정성은 인증하지 않는다.

## 이전 16.08%와 전후 비교

기존 Phase 2의 `performance-jump-steady.json`은 평균 CPU 16.08%, 최대 21.7%, RSS 약 133MiB였다. 이 파일과 기존 2초 CPU stack 표본을 보존했다. 당시 stack에는 main waiting 및 NSHosting/ViewGraph/layout, titlebar/ViewBridge 동작이 보이며, 그 짧은 stack에서 PioOutfit/ImageIO 반복 작업이 확정되지 않았다. 이것만으로 제목 표시줄이나 SwiftUI를 원인이라고 단정할 수 없다.

이번 실제 상점의 우주복 점프(260pt detail sheet, 1040×900 부모 창)를 별도로 20.2초 측정한 결과 평균 CPU 0.000%, ps CPU 평균 0.000%, RSS 139.11MiB였다. 선택값 `점프`는 `shop-astronaut-jump.ax.txt` 및 실제 스크린샷으로 확인했다. 이전 고사용률은 이번 재현에서 관찰되지 않았다.

**16.08% → 0%의 최적화 성과로 보고하지 않는다.** 이전 표본과 이번 진단 루트는 화면 조건이 다르고, 이전 측정의 시스템/창/보조 UI 상태까지 동일하게 재현됐다고 보장할 수 없다. 이번 실제 상점 재현도 단일 짧은 관찰이다. 렌더링 로직을 바꾸지 않았으므로 검증된 전후 개선량은 없다. 고사용률의 정확한 원인은 미확정이며, 다시 재현되는 실행을 Instruments에서 동일 조건으로 잡는 작업이 남아 있다. 증거 없이 레이아웃 차단이나 캐시 정책 변경을 적용하지 않았다.

## Reduce Motion

Mac 시스템 설정의 실제 동작 줄이기 OFF→ON에서 환경값 ON, 활성 rig/track 0/0; OFF 원복 후 1/3으로 복귀했다. iPhone 전용 시뮬레이터의 실제 손쉬운 사용 설정도 같은 OFF→ON→OFF 순서로 확인했고 1/3→0/0→1/3으로 바뀌었다. 두 시스템 모두 원래 OFF 값으로 복구했다. 진단 화면의 '정지 요청 검토' 스위치를 OS 설정 테스트로 대신하지 않았다.

## 제한

iPhone은 빌드/화면/활성 트랙/OS Reduce Motion만 검증했고 비교 CPU·RSS를 측정하지 않았다. Release/실기기/iPad/구형 OS/연속 FPS/스크롤만으로 가려진 상태/장시간 전환은 이번 성능 승인 범위가 아니다. 성능 종합 PASS를 선언하지 않는다. 초기 `performance-baseline-*`는 메뉴 선택/활성 상태 확인이 불완전했던 탐색 표본으로 최종 비교에서 제외한다.

원시 데이터: `performance-controlled-*.json`, `performance-actual-shop-astronaut-jump.json`, 각 대응 `*.ax.txt`. 초기값이 캐시된 macOS AX 부모 Text 대신 갱신된 자식 Text를 계측 증거로 사용했다. 계측 버튼 클릭 자체의 유한한 UI 갱신은 안정화 시간 밖에서 수행했다.
