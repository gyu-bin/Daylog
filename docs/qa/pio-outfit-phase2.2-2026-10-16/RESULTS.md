# 피오 의상 Phase 2.2 — 시각 검토용 결과

기본 피오와 **크리스마스·한복·우주복의 독립 부품 리그**를 DEBUG 검토 화면에 구현했습니다. 기존 13종 원화는 보존했습니다. 전체 상점·대시보드 교체나 성장 1–4단계 대응이 완료된 상태는 아닙니다. 최종 시각 승인은 사용자 검토를 기다립니다.

## 만들어진 것

| 파일럿 | 투명 부품 수 | 독립적으로 움직이는 부분 |
|---|---:|---|
| 기본 피오 | 12 | 눈, 좌우 날개, 새싹, 발 |
| 크리스마스 | 13 | 눈, 오른손, 왼손과 선물 묶음, 모자, 발 |
| 한복 | 12 | 눈, 좌우 소매와 손, 새싹, 발 |
| 우주복 | 14 | 눈, 좌우 장갑과 소매, 새싹, 발 |

총 **51개 부품**을 1254×1254 공통 좌표에 맞췄습니다. 실제 이미지 생성 도구로 가려진 몸체와 연결 뿌리를 재구성했으며, 저해상도 시트 조각을 확대하거나 단순 도형으로 대체하지 않았습니다. 생성 원본의 실제 크기는 1254², 1319×1192, 1536×1024 등입니다. 모두 1536²라고 주장하지 않습니다.

공유 리그는 깜빡임, 한쪽 날개 인사, 양쪽 날개 펄럭임, 제자리 발걸음, 작은 점프, 착지, 기뻐하기, 소품 움직임, 숨쉬기를 지원합니다. 눈·날개 전용 모드에서는 몸통과 상위 레이어가 고정됩니다. 점프와 숨쉬기에서는 조립된 몸 전체가 움직입니다.

크리스마스 왼손과 선물은 실제로 같은 부모 레이어에 연결되어 있습니다. 우주복의 눈은 투명 바이저 뒤에 있으며, 별도 파일인 헬멧과 바이저는 얼굴에 고정됩니다.

## 검증 결과

- **Mac / iPhone Simulator DEBUG 빌드 통과:** `mac-build-final.log`, `ios-build-final.log`.
- **집중 테스트 5개 통과:** `focused-tests-final.log`. 독립 축, 3상태 눈의 배타적 표시, 정지·재개, 공유 그립, 캐시와 리그 해제를 검증했습니다.
- **독립 코드 검토:** `code-review.md`. 51개 부품의 해시·좌표·알파·패킹을 확인했고 수정이 필요한 코드 문제를 발견하지 못했습니다.
- **세 의상 64pt / 220pt, light / dark:** Mac과 iPhone의 실제 앱 화면을 `runtime/final-*`에 저장했습니다. 한복 220pt light는 두 플랫폼의 `after-30-switches` 화면에도 기록되어 있습니다.
- **독립 눈:** 새 크리스마스 실제 영상에서 열린 눈 → 감은 눈 → 반눈을 확인했습니다. 몸·선물·모자는 고정됩니다. Mac 계측도 눈 6개 동작, 몸통 0개입니다.
- **독립 날개:** 한복·우주복의 실제 8초 영상과 0–3.5초의 8개 추출 프레임을 확인했습니다. 얼굴과 몸은 고정된 채 팔 각도가 변하고, 검사한 프레임에서 노출된 뿌리나 틈은 보이지 않았습니다.
- **발걸음·소품:** iPhone의 실제 레이어 상태 JSON 두 표본에서 발의 회전·높이만 변했습니다. 소품 모드에서는 모자와 왼손·선물 부모의 위치가 변하고 손과 선물의 상대 위치는 유지됐습니다.
- **점프·착지·기뻐하기:** 실제 선택 화면과 동작 계측을 확보했습니다. 모든 의상×모드의 모든 프레임을 전수 인증한 것은 아닙니다.
- **Reduce Motion:** 같은 공유 정지 처리의 기존 Mac·iPhone 실제 OS 설정 ON → 동작 0 / OFF 원복 증거를 재사용했습니다. 최종 집중 테스트에서도 정지·재개가 통과했습니다.
- **30회 의상 전환:** 두 플랫폼 모두 리그 1개, 캐시 55개를 유지했습니다. Mac은 실제 스크롤로 화면 밖에 나가면 정지하고 돌아오면 재개됐으며, 뷰 제거 시 리그가 해제됐습니다.
- **CPU·메모리:** `PERFORMANCE.md`와 원시 JSON에 기록했습니다. 초기 iPhone CPU 스파이크도 포함했으며 종합 성능 PASS는 선언하지 않습니다.

iPhone의 추가 스크롤 검증 중 다른 시뮬레이터 화면 전환이 겹쳐 최종 계측을 완료하지 못했습니다. 다른 앱이 찍힌 무효 캡처는 패키지에서 제외했습니다. 유효 화면은 실제 선택값과 JSON 조건을 확인했습니다.

## 남은 제한

1. **성장 1–4단계는 미지원입니다.** 네 단계의 녹색 원화는 각각 존재하지만, 정면의 깨끗한 몸체·단계별 날개와 새싹·의상 부착 좌표가 부족합니다. 현재 파일럿은 각각 한 가지 체형이며 모든 manifest는 `supportsGrowthStages=false`입니다. Lv.1–9 / 10–24 / 25–49 / 50+ 계산은 변경하지 않았습니다. 정확한 누락은 `growth-stage-readiness.md`에 있습니다.
2. **나머지 10종은 확장하지 않았습니다.** 원본을 보존했으며 새 독립 부품 리그는 아직 없습니다.
3. **모든 장식이 별도로 움직이지는 않습니다.** 크리스마스 모자·새싹·방울은 한 부품입니다. 한복의 옷감·꽃·술과 우주복의 버튼·호스·부츠 소매는 몸체에 남아 있습니다. 천이나 유리의 물리 시뮬레이션은 없습니다.
4. **재구성은 픽셀 동일 복원이 아닙니다.** 우주복 팔은 원본보다 조금 길고 눈이 조금 둥글며, 기본 피오의 새싹과 발 시점에도 작은 차이가 있습니다. 원본 대비 이미지를 통한 귀여움·정체성 최종 승인이 필요합니다.
5. **현재는 격리된 DEBUG 검토 경로입니다.** 기존 상점·대시보드의 평면 의상을 자동 교체하지 않았습니다. 단계별 부착 검증 전에 성장 호환을 주장하지 않습니다.
6. **추가 성능 검증이 남았습니다.** 실기기, Release, FPS·GPU·배터리, 장시간 메모리, iPhone 스크롤 정지가 대상입니다. 이전 16.08% CPU의 정확한 병목은 미확정이며 이번 결과를 개선율로 표현하지 않습니다.

## 보존과 산출물

기준 554개 파일 중 이번 작업이 변경한 기존 파일은 RootView의 DEBUG 분기와 프로젝트의 Release 에셋 제외 설정 2개뿐입니다. 나머지 기존 변경과 원본 PNG 14개(13종 의상+기본)는 동일 해시입니다. SwiftData·CloudKit·실제 구매·배포 앱을 수정하지 않았고 커밋·푸시·배포하지 않았습니다. HEAD도 `702e611aa1a95323bb1a78e27772d583972c383a` 그대로입니다.

- `review.html`: 원본/조립 비교와 대표 영상.
- `selected-assets.json`: 선택 부품 51개, 해시와 출처.
- `RIGGING.md`: 좌표, 부모 관계, 부착 방법과 제한.
- `generation-prompts.json`: built-in image_gen으로 재구성한 전체 프롬프트와 실제 출력 출처.
- `runtime/preview-*-8s.mp4`: 실제 iPhone 녹화의 약 1–9초 발췌입니다. 실제 파일 길이는 크리스마스 7.933초, 한복·우주복 각각 8.000초입니다. 재생 속도는 바꾸지 않았습니다. 출력 30fps는 앱의 FPS 측정치가 아닙니다.
- `runtime/preview-*-contact.png`: 실제 영상에서 추출한 프레임 비교.
- `Pio-Outfit-Phase2.2-Review.zip`: 선택 투명 부품, 생성 출처, 비교, 실제 영상, 검토·성능·빌드·테스트 결과.
