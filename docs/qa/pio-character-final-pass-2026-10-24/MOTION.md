# 피오 홈 모션 — 일반 실행 경로 통합

## 구현 범위

기존 `PioOverhaulCharacter.swift`는 보호 대상이며 `#if DEBUG` 안에 있다. 이 파일을 변경하거나 Release에 DEBUG 플래그를 켜지 않았다. `scripts/pio/generate_home_production.py`가 그 파일의 **액션·명세·리소스·리그 정의만** 새 이름 공간으로 생성한다. 키프레임, 피벗, 소품 손 연결, 레이어 순서, 타이밍 계산은 동일하다. 별도로 관리하는 두 번째 모션 알고리즘이 아니다. `--check`는 생성 결과를 원본으로 다시 계산해 바이트 단위로 비교한다.

새 `PioHomeProduction.xcassets`는 기존 14개 등록의 213개 부품 참조만 포함한다. SHA256이 같은 PNG를 하나의 이름으로 공유하므로 실제 PNG는 146장이다. 모든 PNG는 기존 파일의 바이트 복사이며 확대·크롭·재생성이 없다. 각 참조의 원본/대상/SHA256은 `home-production-provenance.json`에 기록했다. 캔버스는 1254 좌표계, 개별 부품 크기·rect·pivot은 원본과 같다. 클라우드 후보 이미지나 미승인 휴가 원화를 홈 카탈로그에 넣지 않았다.

`PioAppearanceView`의 dashboard/growth 및 `PioHeaderCompanion`은 일반 실행에서도 이 경로를 선택한다. 옷장·클라우드·휴가 등의 표시 경로는 이 변경으로 치환하지 않는다. 기존 홈 레이아웃과 캐릭터 영역 크기는 유지한다.

## 권한과 상태

- 기존 `PioAppearanceCoordinator`가 결정한 `outfit`, `requestedOutfit`, `access`만 소비한다. 구매 시스템은 변경하지 않는다.
- 유료 의상은 verified 및 요청 의상과 실제 의상이 일치해야 한다. testing은 기존 DEBUG 해석만 허용하며 Release에는 해당 분기가 없다.
- checking / verificationUnavailable은 캐릭터를 숨겨 권한 확인 도중 기본 피오가 잠깐 보이는 현상을 막는다. 미소유 상태에서 무료 기본 피오로 돌아오는 기존 정책은 유지한다.
- preview 권한으로 실제 홈에 유료 의상을 표시하지 않는다. 그림 파일이 있다는 사실은 권한이 아니다.
- 모션 중 의상 변경은 이전 트랙과 완료 작업을 취소하고 새 의상을 구성한다.

## 10가지 동작과 사용처

아래 시간은 보호된 리그의 한 사이클이다. 일반 홈에서는 idle을 제외하고 한 사이클만 재생하며 완료 후 idle로 돌아온다. 터치 중 재터치는 기존 상호작용 상태가 차단한다.

| 액션 | 시간 | 실제 홈 사용처 | 비고 |
|---|---:|---|---|
| idle | 3.6초 | 대기, 모든 반응 종료 후 | 눈 상태 교체·몸통 호흡. 점프 없음 |
| bounce | 1.2초 | 사용처 미정, 라이브러리 보존 | 기존 두 번 통통 뛰기 |
| walk | 1.8초 | 사용처 미정, 라이브러리 보존 | 발이 번갈아 움직임; 홈을 임의로 돌아다니게 하지 않음 |
| jump | 2.2초 | 터치 순환 두 번째 | 웅크림·상승·낙하·착지 포함 |
| landing | 1.5초 | 독립 사용처 미정, 라이브러리 보존 | 점프 내부 착지와 별개의 회복 모션 |
| celebrate | 2.6초 | 기존 성장 이벤트 카드 | 기존 실제 GrowthEvent 연결 유지 |
| greet | 2.8초 | 터치 순환 첫 번째 | 소품을 든 의상은 기존 자유 손 규칙 유지 |
| sleepy | 4.2초 | 기존 루틴 건너뛰기 반응 | 기존 상태 이벤트 연결 유지 |
| surprised | 2.6초 | 사용처 미정, 라이브러리 보존 | 실패 상태에 임의로 연결하지 않음 |
| encourage | 3.8초 | 루틴 완료, 터치 순환 세 번째 | 기존 실제 진행 상태 변화에 반응 |

idle에는 기존 헤더에서 검토했던 작은 날개·자세 트랙을 재사용한다. 인사 회전값의 6%를 17.3초, 몸통 회전값의 18%를 27.6초에 걸쳐 부드럽게 적용한다. 손에 든 소품과 손에 같은 트랙을 적용한 기존 제약이 유지된다. 원본 액션의 동작 시간·자세를 수정하지 않았다.

## 14종 구조 호환 범위

기본, 벚꽃, 여름휴가, 가을, 겨울, 할로윈, 크리스마스, 한복, 카페, 학생, 운동, 비 오는 날, 잠옷, 우주복을 같은 리그가 처리한다. 다음은 원본에서 그대로 가져온 규칙이다.

- 눈 open/half/closed/happy는 같은 눈 위치를 공유하며 안경·선글라스·바이저 뒤에 있다.
- 크리스마스 선물과 두 손, 잠옷 베개와 양 날개는 같은 피벗·최대 2도 회전 트랙을 공유한다.
- 우산과 잡는 손, 컵·주스·책·할로윈 가방·덤벨과 해당 손은 동일한 연결 트랙을 사용한다.
- 모션 전환은 기존 레이어를 재사용한다. 의상이 바뀔 때만 부품이 교체된다.
- 의상 네 성장 단계별 새 그림을 만들지 않았다. 기존 레벨 임계값과 단일 캐릭터 정책을 그대로 유지한다.

**구조 호환과 최종 시각 승인은 별개다.** 14종×10 모션의 동등성 자동 검사, 실제 64/220pt 프레임 및 대표 영상 결과는 최종 RESULTS와 실제 실행 로그에 기록한다. 화면 검토 전에는 완전한 시각 PASS로 보지 않는다.

## 수명주기·접근성

`PioCloudSceneHost`의 기존 네이티브 창/스크롤 가시성 검사를 사용한다. 새 디스플레이 링크나 프레임별 SwiftUI 상태 업데이트를 추가하지 않았다. scenePhase, 화면 표시, 스크롤 가시성, Reduce Motion에 따라 트랙을 시작/중지한다. 화면 이탈 시 모든 트랙 및 유한 액션 완료 Task를 취소한다. 재진입은 오래된 이벤트 재생보다 편안한 idle을 우선한다. Reduce Motion은 중립 자세이며 터치·루틴 이벤트도 움직이지 않는다.

기존 헤더 버튼의 VoiceOver 이름·행동 설명·현재 반응 안내와 일반 화면 레이아웃은 유지한다. 부품별 장식 레이어는 접근성 트리에 노출하지 않는다. 실기기 VoiceOver 낭독 품질은 자동 구조 검사만으로 PASS 처리하지 않는다.

## 검증 준비 및 근거

- 생성기 `--check`: 실행 PASS — 원본 파생 소스와 PNG 바이트 일치.
- 변경 Swift 소스의 parser 검사: 실행 PASS.
- Mac/iOS test build: `mac-build-2.log`, `ios-build-2.log` 각각 TEST BUILD SUCCEEDED. 첫 빌드의 별도 통합 테스트 타입 이름 충돌은 담당자가 모듈 이름을 명시해 수정했다. 테스트 빌드 성공은 실제 테스트/시각 승인이나 Release 빌드 성공과 구분한다.
- `PioHomeProductionTests` 5개 실행 PASS (`mac-first-tests.log`): 14개 리소스/치수, 140개 원본 대 생산 모션 트랙 동등성, 유한 동작/idle 복귀/정지, 권한 거부, 조용한 idle 검사.
- 기존 헤더 interaction/completion 6개 실행 PASS. 홈 native 84캡처 검사 PASS이며 원본 84장을 직접 검토했다. 대표 세 동작은 모두 실제 시간 재생 후 idle 복귀했다. 초기 우주복 응원 검사기의 Y축만 비교한 assertion 실패는 동작의 수평 이동을 놓친 테스트 문제로 분리했고, 수정 후 검사를 별도로 기록한다. Release 빌드/기타 기기/실제 권한 장면 검증은 최종 RESULTS 참조.

## 클라우드·휴가와의 구분

홈 승격이 클라우드의 태블릿 자세나 휴가의 누운 자세를 대체하지 않는다. 클라우드의 기존 14종 눈·손·태블릿 리그는 유지한다. 휴가 눈·음료·고정 줄의 실제 독립 정도와 낮·밤 적용 결과는 이번 휴가 담당의 ASSETS/RESULTS 및 원본 native 영상으로 별도 평가한다. 홈 리그 성공을 근거로 부족한 휴가 손/소품을 완료 처리하지 않는다.

## 독립 코드 리뷰에서 발견한 통합 결함 및 수정

검토 후 wrapper 상태 전이 두 곳을 추가 수정했다. 보호된 원화/키프레임/이벤트 데이터는 그대로다.

1. 최초 SwiftUI host 생성은 `visible=false`라서 non-idle 요청이 비활성 상태로 저장된다. 기존 wrapper는 이어지는 최초 활성화를 이미 재생된 요청의 복귀로 오인해 idle로 버렸다. 이제 `requestStarted`를 기록해 **한 번도 시작하지 않은 요청은 최초 활성화 때 재생**하고, 이미 재생된 요청만 화면/백그라운드 복귀 때 idle로 정리한다.
2. 기존 성장 카드의 일반 XP 버블은 1.8초에 사라지지만 축하 원래 길이는 2.6초다. 버블이 사라져 upstream이 idle을 요청하면 기존 wrapper가 축하를 잘랐다. 이제 같은 의상의 활성 finite action 도중 들어온 idle 요청은 기록만 하고 **기존 action의 실제 완료 시점까지 유지**한다. 새로운 non-idle 요청, 의상 교체, 화면 이탈 및 Reduce Motion은 즉시 이전 작업을 취소한다. UI 버블 표시 시간을 늘리지 않았다.

새 실제 시간 회귀 3개는 manual settle을 호출하지 않는다: 최초 inactive→active/재개/다른 의상의 대기 요청, 실제 1.8초 후 idle을 받은 축하가 2.6초에 완료됨, 의상 변경으로 취소된 2.2초 점프의 종료가 새 3.8초 응원을 끊지 않음. 실제 실행 결과는 build6 이후 로그로 별도 기록한다. 이전 5개 PASS를 새 3개 PASS로 확대 해석하지 않는다.

최초 8개 회귀 실행에서 7개 PASS, 성장 버블 검사 1개 FAIL (`mac-home-fixes-tests.log`). 1.8초 시점의 displayedAction은 celebrate이고 실제 완료는 2.604초였으나, 비표시 CALayer에서 x 이동 트랙을 조회한 값이 nil이었다. 이를 앱 결함이나 테스트 결함으로 아직 단정하지 않았다. 검사를 실제 NSWindow/UIWindow 렌더 트리에 연결하도록 보완하고 시작/1.8초의 키·presentation 기록을 추가했다. 2.6초 duration/실제 경과/자동 idle assertion은 유지했다. 다음 실행 결과로 최종 판정한다.

C8 결과: `mac-build-8-retry.log` TEST BUILD SUCCEEDED, `mac-home-hosted-C8-tests.log` **8/8 PASS**. 실제 창에 붙인 성장 버블 검사에서 시작과 1.8초 양쪽 모두 이동/회전/크기 5개 트랙이 남아 있고 presentation=true였다. 2.6초 duration assertion과 실제 자동 idle 복귀가 모두 통과(검사 2.642초)했다. 따라서 앞선 nil 트랙은 비표시 CALayer를 비동기 시간 경과 후 검사한 fixture 문제로 분리한다. 앱 모션 타이밍, assertion, 대기 예산은 변경하지 않았다. 최초 inactive 요청/재개 및 의상 교체 후 과거 deadline 취소 검사도 실제 시간으로 PASS했다. 처음 sandbox 캐시 접근 실패는 `mac-build-8.log`에 보존하고, 같은 명령을 필요한 Xcode 권한으로 재실행한 결과와 구분한다.
