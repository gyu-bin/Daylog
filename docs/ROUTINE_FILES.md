# 루틴 파일 형식

설정 → 가져오기 · 내보내기에서 CSV 양식을 저장하거나 활성 루틴을 내보낼 수 있다. 파일 선택 자체는 읽기 전용이며 검증 결과와 미리보기를 확인하고 저장을 승인해야 새 루틴이 생긴다. 전체 백업 JSON은 가져오기 대상이 아니다.

## CSV

UTF-8, 첫 행은 아래 열 이름과 순서를 그대로 쓴다. UTF-8 BOM, CRLF/LF, 따옴표로 감싼 쉼표·개행과 이중 따옴표를 지원한다.

```csv
group,title,weekdays,time,note
건강,가볍게 걷기,1;2;3;4;5,08:00,20분
독서,책 읽기,6;7,저녁,"책 10쪽, 메모 남기기"
```

요일은 월요일=1, 일요일=7. 1개 이상, 중복 없이 세미콜론으로 나열한다. 그룹명 40자, 루틴명 60자, 시간 12자, 메모 10,000자 이하. 이름과 시간 앞뒤 공백은 자동 제거하지 않고 오류를 표시한다. 시간은 기존 Daylog처럼 자유 문구도 가능하지만 `25:99`처럼 잘못된 시각은 거부한다. 알림은 해석할 수 있는 시각만 사용한다. 한 파일 최대 5MB·1,000개 루틴.

## 루틴 JSON

```json
{
  "format": "daylog.routines",
  "version": 1,
  "routines": [
    {"group": "건강", "title": "가볍게 걷기", "weekdays": [1,2,3,4,5], "time": "08:00", "note": "20분"}
  ]
}
```

요일 배열 이외에는 문자열이다. CSV와 같은 검증 규칙을 적용한다. 그룹·루틴 ID와 과거 이력은 루틴 가져오기 형식에 없다. 활성 루틴만 내보내며 보관·삭제 항목까지 보존하려면 전체 기록 JSON을 사용한다.

같은 그룹명을 재사용하고 동일 그룹/루틴 이름과 설정이 모두 같으면 중복으로 건너뛴다. 설정이 다르거나 같은 이름 그룹이 여러 개거나 보관·삭제된 이름과 충돌하면 오류를 표시하고 덮어쓰지 않는다. 저장 직전 데이터·날짜가 달라졌으면 미리보기를 다시 확인해야 한다.

## 전체 기록 JSON

`format=daylog.backup`, `version=1`, `schemaVersion=4`. `entities`에 7개 엔티티의 물리 행을 담고, 중복·보관·삭제·숨김 행과 FieldEdit 충돌 이력·휴가 tombstone도 보존한다. `vacations`는 현재 해석된 휴가의 보조 목록이다.

날짜 값은 JSON Double인 2001-01-01 UTC 이후 초, Data는 base64, 없는 필드는 null이다. DayRecord/DayCheck 관계는 이 파일 안의 rowID로 연결된다. 내보내는 동안 모델 저장·병합을 수행하지 않는다. 현재 로컬에 도착한 기록만 포함하며 아직 iCloud에만 있는 내용은 보장하지 않는다. **이번 버전에는 전체 기록 복원 기능이 없다.**

내보내기에서도 검증한다. 같은 그룹명이 서로 다른 그룹을 가리키거나 동일 그룹/이름의 루틴 ID가 여러 개거나 값이 가져오기 제한을 넘으면 루틴 CSV/JSON 저장을 중단하고 전체 JSON을 안내한다. 이 제한은 다시 가져올 때 그룹이 합쳐지거나 루틴 개수가 줄어드는 것을 막는다.
