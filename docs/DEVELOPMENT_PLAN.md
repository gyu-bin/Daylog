## Phase 5 계획

| 단계 | 범위 | 상태 | 먼저 정할 것 |
|---|---|---|---|
| 5-A | 루틴 상태(건너뛰기), 루틴별 최근 기록, macOS 사이드바 색 | 구현·검증 완료(2026-10-13). 배포 전 | 없음. 저장 형식 변경 없이 기존 체크 편집 기록을 썼다 |
| 5-B | 대시보드 꾸미기: 텍스트 카드, 섹션 제목, 구분선, 상단 배경 | 구현·검증 완료(2026-10-13). 배포 전 | 확정: 이미지 카드는 새로 만들지 않고(기존 것은 유지), 사진의 iCloud 동기화는 하지 않는다. 텍스트 카드 내용은 기존 `FieldEdit`로 공유, 배치·크기·사진은 기기별 |
| 5-C | 공식 템플릿 탐색·가져오기 | 구현·검증 완료(2026-10-13). 배포 전 | 템플릿은 앱에 내장(11개). 가져오기는 기존 루틴 가져오기 서비스를 재사용하고, 겹치는 줄은 건너뛴다 |
| 5-D | 사용자 간 템플릿 공유: 내 루틴을 템플릿 파일(`.daylogtemplate`, JSON)로 만들어 시스템 공유·저장, 받은 파일 가져오기 | 구현·검증 완료(2026-10-13). 배포 전 | 확정: 서버 없이 파일로 주고받는다. 공식 템플릿 11개와 같은 미리보기·가져오기를 쓴다 |
| 5-D1 | (보류) 공개 템플릿 서버: Supabase 스키마·RLS, 인증, 게시·관리·신고·차단 | 앱 코드와 SQL은 남겨 두고 꺼 둠. SQL 미실행, 서버 미연동 | [COMMUNITY.md](COMMUNITY.md). 다시 진행하려면 프로젝트 생성·RLS 검사·Apple 로그인 권한·macOS 네트워크 권한의 승인이 필요하다 |
| 5-E | 대시보드 템플릿 공유 | 미착수 | 5-B의 배치 형식 확정 뒤. 다른 기기 크기에서의 재배치 규칙 |

- 5-B 이후는 새 저장 형식이나 서버가 필요할 수 있다. SwiftData·CloudKit Production 스키마를 바꿔야 하면 영향과 마이그레이션 방안을 먼저 보고하고 승인받는다.
- 5-C·5-D·5-E는 사용자 기록(체크·식사·휴가)을 내보내지 않는다. 템플릿에는 루틴 정의와 배치만 담는다.

## 작업 및 안전 원칙

- 로컬 main에서 작업하며 새 복제·브랜치를 만들지 않는다. 작업 시작 시 상태를 확인하고 기존 변경을 보존한다.
- SwiftData v4와 CloudKit 구성을 유지한다. 파괴적 마이그레이션·Production 변경은 승인 없이 하지 않는다.
- 기능별 관련 테스트를 먼저 실행하고 마지막에 전체 회귀를 한 번 실행한다. macOS/iOS Debug·Release 및 가능한 시뮬레이터 UI를 검증한다.
- 기능 완료·실패·보류마다 PROGRESS.md를 갱신한다. 테스트하지 않은 환경은 명시한다.
- 이번 요청은 최종 main 커밋·push를 허용한다. 실제 릴리스 게시·서명 변경은 별도 승인이 필요하다.
